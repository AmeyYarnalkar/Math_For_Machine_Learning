## How dot product is used in cosine similarity

**Cosine similarity = dot product, but normalized.**

It answers:

> “How similar are the directions of two vectors, ignoring their size?”
> 

---

## Step-by-step intuition

### 1️⃣ Dot product alone

Dot product tells:

- Same direction → big number
- Perpendicular → 0
- Opposite → negative

**Problem:**

Big vectors give big dot products **even if direction isn’t that similar**.

---

### 2️⃣ Fix the problem: normalize by length

So we divide by the magnitudes (lengths) of both vectors.

That gives us **pure direction similarity**.

---

## Formula (don’t panic, read the meaning)

```
cosine similarity =
(A · B) / (|A| × |B|)

```

Meaning:

- **A · B** → how aligned they are
- **|A| × |B|** → remove size effect

---

## What the result tells you

- **1** → same direction (very similar)
- **0** → no relation
- **1** → opposite direction

---

## Simple example (words, not numbers)

- Two documents using **similar words**
    
    → vectors point same way
    
    → high cosine similarity
    
- Two documents on **different topics**
    
    → vectors point differently
    
    → low cosine similarity
    

---

## Why ML loves cosine similarity

Because in ML we often care about:

- **Pattern similarity**, not raw magnitude
- Text similarity
- Recommendation systems
- Embeddings (words, users, items)

---

## One line to remember forever

> Cosine similarity uses dot product to measure direction similarity, not size.
> 



---

## What is **size effect**? 

**Size effect = big vectors give big dot products even if they are NOT more similar.**

Dot product depends on **two things at once**:

1. Direction (alignment)
2. Size (length / magnitude)

That’s the problem.

---

### Intuition example (no math fear)

Imagine two arrows pointing **in the same direction**:

- Arrow A: length = 2
- Arrow B: length = 100

Dot product will be **huge**, not because they’re *more similar*, but because **B is long**.

So the model gets fooled:

> “These are very similar”
> 
> 
> when actually they’re just **big**.
> 

That unwanted influence is called **size effect**.

---

### Why this is bad in ML

In text / embeddings:

- Long documents → larger vectors
- Short documents → smaller vectors

Dot product would say:

> “Long doc = more similar to everything”
> 

Which is wrong.

So we **remove size**.

---

## How we remove size → magnitude ( |A| )

### What is |A| ?

**|A| = length of the vector**

It tells:

> “How big is this vector?”
> 

---

### Formula for |A| (vector magnitude)

For a vector:

```
A = (x, y)

```

Magnitude:

```
|A| = √(x² + y²)

It is derived from the formula √(x2 - x1)^2 + (y2 - y1)^2 this distance formula is used here the other point is considered to be origin thats why 
```

For 3D:

```
A = (x, y, z)
|A| = √(x² + y² + z²)

```

Same idea in higher dimensions.

---

### Geometric intuition

- Vector = arrow
- Magnitude = arrow length
- Calculated using **Pythagoras**

---

## How cosine similarity fixes size effect

```
cosine similarity =
(A · B) / (|A| × |B|)

```

What this does:

- Dot product → checks alignment
- Divide by magnitudes → cancels size

So only **direction** remains.

---

## One-line takeaway (lock this in)

> Size effect is when vector length inflates similarity; magnitude normalization removes it.
>
